# Dữ liệu giả để test từng API

Đây là dữ liệu mẫu gửi vào **backend thật**. Các tài khoản, genre, artist, release, song tạo qua request sẽ được lưu thật trong database/MinIO của môi trường bạn chọn.

## Test nhanh bằng Postman

Import lại collection và environment mới trong thư mục này. Nếu Postman đang giữ environment cũ, giữ lại thông tin đăng nhập bạn đã điền khi cập nhật.

| Bộ | Thiết lập | Tự làm gì |
|---|---|---|
| Auth & Users / Nhajc Local | `autoGenerateUser=true` | Register tự sinh username, email, mật khẩu và lưu token; các request tiếp theo dùng tài khoản vừa tạo |
| Admin / Nhajc Admin Local | `autoGenerateData=true` | Tự sinh tên genre, artist, release và tiêu đề bài hát; ngày release lấy ngày hiện tại theo UTC+7 |
| Admin / Nhajc Admin Local | Chọn File trong form-data | `avatar` cho artist, `cover` cho release; dùng PNG mẫu trong fixtures hoặc ảnh của bạn |

Với Admin, bạn vẫn cần điền `adminUsername`, `adminPassword` của tài khoản đã có role ADMIN. Không thể fake token hoặc role để vượt qua phân quyền.

Chạy theo thứ tự Login Admin → Create genre → List genres → Create artist → Create release → Upload song → các request Audio. Các ID được lấy từ response và lưu vào environment, không phải UUID ngẫu nhiên. Khi tạo release mới, collection xóa songId của lần trước và đặt trackNumber=1.

List genres nhận `genrePage=0`, `genreSize=20` trong environment. Response là `{content,page,size,hasNext}`; tăng genrePage thêm 1 khi hasNext=true để lấy trang tiếp theo. Genre vừa tạo có thể nằm ở trang khác do danh sách sắp theo tên.

Các trường như `artistName`, `releaseTitle`, `releaseType`, `releaseDate`, `songTitle` đều nằm trong environment. Muốn tự nhập tên/title/ngày, đặt `autoGenerateData=false`. `releaseType` mặc định là ALBUM; có thể đổi thành SINGLE/EP/COMPILATION.

Tất cả upload ảnh dùng **Body → form-data**: Create artist có `name` (Text), `avatar` (File); Create release có metadata (Text), `cover` (File). Không chọn ảnh thì bỏ chọn dòng File; script cũng bỏ part ảnh chưa có file. Không gửi Base64, đường dẫn ở ô Text hay chuỗi null. Không tự đặt header Content-Type. Với release, lặp lại dòng `artistIds`/`genreIds` (Text) cho từng UUID, ngày `yyyy-MM-dd`; không có genre thì bỏ dòng `genreIds`.

## File upload mẫu

| File | Dùng cho |
|---|---|
| [demo-avatar.png](fixtures/demo-avatar.png) | PNG 2×2 pixel để test upload avatar/ảnh. Đây là ảnh kỹ thuật rất nhỏ |
| [demo-tone.flac](fixtures/demo-tone.flac) | Âm sin 440 Hz dài 2 giây, stereo 44.1 kHz/16-bit, có PNG nhúng; dùng cho upload/chuyển mã/phát audio |
| [demo-mono.flac](fixtures/demo-mono.flac) | Im lặng 1 giây, mono 16 kHz/16-bit; dùng để test resample trước mã hóa AAC |

Trong Postman, chọn file từ máy tại **Body → form-data**, kiểu **File**. Không gõ đường dẫn file vào trường Text. Request upload song/avatar người dùng được bỏ qua nếu chưa chọn file; Create artist/release vẫn tạo được khi bỏ ảnh tùy chọn. Tên file trong tài liệu không tự đính kèm file.

Để test cover lấy từ FLAC: bỏ chọn dòng File `cover`, tạo release mới rồi upload demo-tone.flac.

## Mẫu body cho từng API

File [sample-data.json](sample-data.json) có các mẫu register, login, refresh, logout, profile, genre, artist, release, upload song, audio và xóa comment. Đây là file tham khảo body, **không phải collection để Import**.

- Register dùng username/email mới mỗi lần; gửi lại sẽ nhận 409. Collection Auth đã tự tạo hậu tố ngẫu nhiên để tránh lỗi này.
- Genre không được trùng tên, kể cả khác hoa/thường. Collection tự thêm hậu tố cho tên mẫu.
- Release phải dùng artistId/genreId có thật; không thay bằng UUID tự sinh.
- Upload song phải dùng releaseId thật và trackNumber chưa có trong release. Muốn upload tiếp vào cùng release, tăng trackNumber.
- API đọc dùng ID và token từ các bước trước, không cần body giả.
- Delete comment cần commentId đang tồn tại. Đã có POST `/songs/{songId}/comments` để tạo comment và lấy commentId. Bộ Catalog & Library test đầy đủ luồng này. Nếu cần chèn dữ liệu thủ công, có thể dùng [create-demo-comment.sql](fixtures/create-demo-comment.sql) trong Navicat trên database test: thay USER_ID bằng ID user trong response Login và SONG_ID bằng ID bài hát vừa upload, chạy câu lệnh rồi lấy id trả về để điền commentId. Câu SQL tạo một bình luận thật; request DELETE sẽ xóa bình luận đó.

Collection Auth có sẵn các ca lỗi 400/401/409. Collection Admin có ca genre trùng (409) và release không có artist (400). Các ca này pass khi server trả đúng lỗi mong đợi.
